## [Unreleased]

### Безопасность
- **Разделены секрет вебхука и код приглашения.** Раньше `webhook_token`
  использовался и как секрет `/alice/...`, и как код в ссылке-приглашении —
  то есть утекал каждому подписчику, который мог инициировать ложный SOS.
  Теперь ссылки-приглашения используют отдельный `subscribe_code`, а
  `webhook_token` подписчикам не показывается. Миграция бесшовная (URL Алисы
  у владельцев не меняется), старые ссылки продолжают работать (fallback).
- Команда `/rotate` — сменить утёкший секрет вебхука (выдаёт новый URL Алисы;
  ссылки-приглашения при этом не меняются).
- `/openapi.json` отключён (`FastAPI(openapi_url=None)`); токены — 256-битные
  (`secrets.token_urlsafe`).

### Добавлено
- **Двойная доставка Telegram + MAX по номеру.** Если у подписчика указан
  телефон, SOS дублируется ему и в MAX (через сервисный userbot), и подписчик
  может ответить в любом из мессенджеров — ответ придёт владельцу с правильным
  именем. Ответ из MAX сопоставляется с владельцем по номеру телефона.

### Исправлено
- Вход MAX-userbot переживает истёкший SMS-код / лимит попыток / обрыв связи:
  авто-повтор с задержкой (запрашивает новый код) вместо падения до пересборки.
- Поддержка пароля 2FA для MAX-userbot (`MAX_USERBOT_PASSWORD` или `/maxpassword`).

## [1.0.0] — 2026-07-11

Первый публичный релиз мультиарендного сервиса экстренного оповещения
«Alisa SOS»: голосовая команда Яндекс Алисе → мгновенные сообщения близким
в Telegram и MAX.

### Возможности

**Экстренный SOS**
- Голосовой SOS через навык Яндекс Алисы (персональный webhook на владельца)
- Выбор адресата: всем контактам сразу или одному по имени
- Дополнительное сообщение голосом
- SOS и тест-рассылка из бота (`/sos`, `🆘 Тест SOS`)

**Два мессенджера — Telegram и MAX**
- Владельцы и подписчики независимо выбирают Telegram или MAX
- Кросс-платформенная доставка: SOS, ответы и авточек уходят каждому на его платформу
- Полный паритет функций в MAX-боте (`maxapi`); включается через `MAX_BOT_TOKEN`

**Ответы контактов**
- Двусторонняя связь: подписчик пишет боту — владелец получает уведомление
- Алиса зачитывает ответы и предлагает ответить голосом
- Умная маршрутизация ответа: тому, кто присылал SOS последним; при нескольких
  SOS за последний час — выбор кнопками
- Ответы подписываются именем контакта (в т.ч. переименованным)

**Управление**
- Кнопочный интерфейс, настройки через меню (имя, текст SOS, часовой пояс)
- Переименование подписчиков — удобные для Алисы имена
- Ссылки-приглашения для друзей (Telegram и MAX)

**Авточек (dead-man switch)**
- Ежедневная проверка «Всё в порядке?»; нет ответа 1 ч → повтор, +30 мин →
  предупреждение, +10 мин → автоматический SOS всем контактам

**Администрирование**
- Одобрение регистраций админом (`ADMIN_CHAT_ID`), панель `/admin`
- Удаление аккаунтов владельцев со всеми связанными данными

**Резервное копирование**
- `/backup` — архив всех `.db` файлов документом в чат
- Авто-бэкап каждые `BACKUP_INTERVAL_HOURS` часов
- Шифрование архивов (`BACKUP_PASSPHRASE`, AES-256-GCM)
- Восстановление: файл боту с `/restore` в подписи → подтверждение → страховочный
  бэкап → замена базы → отчёт
- Скрипты `scripts/backup.sh` и `scripts/restore.sh` для cron/офлайн-хранения

### Технологии
- Python 3.12, FastAPI + uvicorn, aiogram 3, maxapi, SQLite (aiosqlite), Docker
- Развёртывание через docker compose, Nginx + HTTPS, автоматическая миграция схемы БД
