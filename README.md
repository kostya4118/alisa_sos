# Alisa SOS

Сервис экстренного оповещения: голосовая команда Яндекс Алисе → мгновенные сообщения в **Telegram и/или MAX** всем нужным людям.

Работает как **мультиарендный** сервис: любой человек может зарегистрироваться в боте, получить собственный URL для навыка Алисы и свою ссылку для подписчиков — без пересечения с другими пользователями.

**Два мессенджера, независимый выбор.** Владельцы и подписчики могут пользоваться Telegram или MAX по отдельности: TG-владелец может иметь MAX-подписчиков и наоборот. SOS, ответы и авточек автоматически доставляются каждому на его платформу. Поддержка MAX опциональна и включается переменной `MAX_BOT_TOKEN` (без неё сервис работает только с Telegram, как прежде).

## Как это работает

```
Пользователь говорит Алисе:
«Алиса, открой навык С О С»
        │
        ▼
Яндекс Диалоги вызывают вебхук:
POST https://ваш-домен.ru/alice/{webhook_token}
        │
        ▼
Алиса уточняет детали
(кому отправить, добавить ли сообщение)
        │
        ▼
Бот рассылает SOS в Telegram
всем подписчикам владельца
        │
        ▼
Контакты могут ответить — Алиса
зачитает ответы при следующем открытии
и предложит написать им в ответ
```

### Диалог с Алисой

```
Вы:    «Алиса, открой навык С О С»
Алиса: «Есть 2 новых ответа от ваших контактов. Зачитать?»
Вы:    «Да»
Алиса: «Мама написал: еду к тебе. Петя написал: буду через 10 минут.
        Хотите ответить? Назовите имя или скажите пропустить. Писали: Мама, Петя.»
Вы:    «Маме»
Алиса: «Что передать Мама?»
Вы:    «Жду тебя, спасибо»
Алиса: «Ответ отправлен Мама. Отправить SOS всем 3 контактам или одному?»
Вы:    «Одному»
Алиса: «Кому? Назовите имя. Доступные: Мама, Петя, Маша»
Вы:    «Маше»
Алиса: «Отправить SOS контакту Маша Иванова?»
Вы:    «Да»
Алиса: «Хотите добавить сообщение?»
Вы:    «Я застряла в лифте»
Алиса: «SOS отправлен контакту Маша Иванова. Держитесь!»
```

## Возможности

### Экстренный SOS

- **Голосовой SOS** — достаточно сказать Алисе одну фразу
- **Выбор адресата** — всем сразу или конкретному человеку по имени
- **Дополнительное сообщение** — можно голосом уточнить, что случилось
- **SOS через бота** — кнопка «🚨 Отправить SOS» или команда `/sos` с подтверждением
- **Тест рассылки** — «🆘 Тест SOS» отправляет тестовое сообщение с пометкой

### Ответы контактов

- **Двусторонняя связь** — подписчик пишет боту любой текст, владелец получает уведомление немедленно
- **Алиса зачитывает ответы** — при открытии навыка: «Есть N новых ответов. Зачитать?»
- **Ответ голосом** — после зачтения Алиса предлагает ответить каждому контакту прямо через колонку
- **Проверка перед SOS** — перед каждым «Отправить SOS?» Алиса проверяет наличие новых ответов
- **Кнопка «📬 Ответы»** — просмотр непрочитанных ответов в Telegram

### Авточек (dead-man switch)

Необязательная функция. Если включена — бот ежедневно в указанное время спрашивает «Всё в порядке?».

```
09:00 — 👋 Ежедневная проверка. Всё в порядке?
          [✅ Всё хорошо]  [🆘 Нужна помощь]

  нет ответа 1 час →

10:00 — ⚠️ Вы не ответили час назад. Всё хорошо?

  нет ответа 30 минут →

10:30 — 🚨 Последняя проверка! Если не ответите 10 минут — SOS уйдёт автоматически.

  нет ответа 10 минут →

10:40 — 🆘 Авто-SOS разослан всем контактам
```

Любое текстовое сообщение боту также подтверждает проверку. Кнопка «🆘 Нужна помощь» отправляет SOS немедленно.

Настройка: `⚙️ Настройки → ⏰ Авточек`

### Управление

- **Кнопочный интерфейс** — все действия доступны через кнопки, команды помнить не нужно
- **Переименование подписчиков** — задайте контакту имя, которое Алисе легко произнести и распознать
- **Настройки через меню** — имя, текст SOS, часовой пояс — редактируются кнопками без команд
- **Мультиарендность** — каждый пользователь изолирован, данные не смешиваются
- **Часовой пояс** — время в SOS-сообщениях и авточеке показывается в вашем часовом поясе
- **Ссылка-приглашение** — подписчики добавляются одним нажатием по личной ссылке

### Поддержка MAX (опционально)

- **Два мессенджера** — Telegram и [MAX](https://max.ru) работают параллельно
- **Независимый выбор** — владелец и каждый подписчик сами выбирают мессенджер
- **Кросс-платформенная рассылка** — SOS/ответы/авточек уходят получателю на его платформу
- **Полный паритет** — в MAX доступны регистрация, одобрение, настройки, контакты, SOS, ответы и авточек
- **Две ссылки для друзей** — владелец делится ссылкой Telegram или MAX в зависимости от мессенджера друга
- **Одобрение через Telegram** — заявки MAX-владельцев приходят админу в Telegram

#### MAX через userbot (без бота, по номеру)

Альтернатива боту MAX — **сервисный аккаунт** на библиотеке [PyMax](https://github.com/MaxApiTeam/PyMax)
(вход по номеру + SMS). Включается через `MAX_USERBOT_PHONE`. Тогда:

- писать можно **любому** пользователю MAX **по номеру телефона** — без верификации юрлица и без «запуска бота»;
- владелец добавляет MAX-подписчика командой `/addmax Имя +79991234567`;
- SOS/сообщения этому контакту уходят через сервисный аккаунт (`messaging` роутит MAX → userbot по номеру);
- при первом старте бот просит у админа SMS-код: `/maxcode 1234`; статус — `/maxstatus`; сессия хранится в `data/max_session/` (попадает в бэкапы).

⚠️ **Неофициальный API MAX** — может сломаться при обновлении мессенджера, а аккаунт могут заблокировать.
Используйте как **резервный** канал; основной — Telegram.

**Стек:** Python 3.12, FastAPI, uvicorn, aiogram 3, maxapi, SQLite, aiosqlite, Docker.

### Схема базы данных

```sql
owners    — зарегистрированные владельцы (поле platform: telegram | max)

replies   — ответы подписчиков (поле platform)
checkins  — настройки и состояние авточека каждого владельца
```

## Быстрый старт для нового пользователя

Если сервис уже развёрнут — никакой установки не нужно.

### 1. Зарегистрируйтесь как владелец

Найдите бота в Telegram и отправьте `/register`. Бот пришлёт:
- **Webhook URL** — вставьте в настройки навыка Яндекс Диалогов
- **Ссылку для друзей** — поделитесь с теми, кто должен получать SOS

### 2. Добавьте подписчиков

Отправьте друзьям ссылку вида:
```
https://t.me/ваш_бот?start=sub_xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```
Они нажимают «Старт» → автоматически подписываются. Вы получаете уведомление.

### 3. Настройте навык Алисы

Подробная пошаговая инструкция — в разделе [Настройка навыка Алисы по шагам](#настройка-навыка-алисы-по-шагам) ниже. Коротко: создайте навык в Яндекс Диалогах и вставьте персональный **Webhook URL**, который прислал бот.

### 4. Протестируйте

Нажмите **🆘 Тест SOS** — подписчики получат тестовое сообщение. В Яндекс Диалогах используйте встроенный симулятор.

### 5. (Опционально) Включите авточек

`⚙️ Настройки → ⏰ Авточек → Включить` → введите время, например `09:00`.

## Настройка навыка Алисы по шагам

Эта инструкция — для **владельца**, который уже зарегистрировался в боте (`/register`) и получил персональный **Webhook URL**.

📄 Готовый образец заполнения формы (поле за полем) — в [docs/ALICE_SKILL_EXAMPLE.md](docs/ALICE_SKILL_EXAMPLE.md). Этот же пример бот присылает вам автоматически вместе с Webhook URL.

### Что присылает бот

После `/register` (и одобрения админом, если оно включено) бот отправляет сообщение вида:

```
✅ Вы зарегистрированы!

Webhook URL для Яндекс Диалогов:
https://sos.ваш-домен.ру/alice/3f2a9c10-7b4e-4c1a-9e2d-8a1b2c3d4e5f

Ссылки для друзей:
📱 Telegram:
https://t.me/ваш_бот?start=sub_3f2a9c10-...
```

⚠️ **Webhook URL у каждого владельца свой** (в нём ваш персональный токен). Не используйте чужой и не публикуйте свой — по нему отправляется ваш SOS.

Скопируйте строку `https://…/alice/<токен>` целиком — она понадобится на шаге 4.

### Шаг 1. Войдите в консоль разработчика

1. Откройте **[dialogs.yandex.ru/developer](https://dialogs.yandex.ru/developer)**
2. Войдите под своим Яндекс-аккаунтом (тем же, что на колонке/в приложении Алисы)
3. Нажмите **«Создать диалог»** → выберите тип **«Навык в Алисе»**

### Шаг 2. Заполните вкладку «Настройки»

| Поле | Значение |
|---|---|
| **Название** | `СОС` (или любое — оно для каталога) |
| **Активационное имя** | `сос` — фраза, которой вы будете звать навык |
| **Голос** | любой (например, Алиса/Оксана) |
| **Язык** | Русский |
| **Имя разработчика** | ваше имя или ник |
| **Официальный навык** | нет |

**Про активационное имя.** Это слово, после которого Алиса запускает навык: «Алиса, **открой сос**». Требования Яндекса:

- 2–3 слова работают надёжнее, чем одно короткое
- Алиса плохо распознаёт аббревиатуру «С‑О‑С» по буквам. Лучше выбрать узнаваемую фразу, например `сос помощник`, `мой спасатель` или `экстренный вызов`
- Проверьте поле подсказкой: консоль предупредит, если имя занято или плохо распознаётся

### Шаг 3. (Необязательно) Логотип и описание

Для **тестирования** это не нужно. Понадобится только перед отправкой на модерацию:

| Поле | Значение |
|---|---|
| Описание краткое | Экстренное оповещение близких |
| Описание полное | Навык рассылает SOS-сообщение всем подписанным контактам в Telegram и MAX |
| Категория | Здоровье и фитнес |
| Возрастная категория | 6+ |
| Логотип | изображение минимум 192×192 px |

### Шаг 4. Вставьте Webhook URL (главный шаг)

1. Откройте вкладку **«Настройки»** → блок **«Backend»** (или **«Веб-сервис»** / **«Использовать Webhook»**)
2. Выберите вариант **«Свой навык / Webhook URL»** (НЕ «Навык на Яндекс.Облаке»)
3. В поле **Webhook URL** вставьте строку из сообщения бота **целиком**, вместе с токеном:

   ```
   https://sos.ваш-домен.ру/alice/3f2a9c10-7b4e-4c1a-9e2d-8a1b2c3d4e5f
   ```

4. Нажмите **«Сохранить»**

**Требования к URL:**
- обязательно **HTTPS** с валидным сертификатом (самоподписанный не подойдёт)
- адрес должен быть доступен из интернета (проверьте: `curl https://ваш-домен/health` → `{"status":"ok"}`)
- без слэша на конце, токен — последний сегмент пути

### Шаг 5. Проверьте в симуляторе

1. Перейдите на вкладку **«Тестирование»** (режим «В консоли»)
2. Напишите или скажите: **«открой сос»** (ваше активационное имя)
3. Навык должен ответить, например: *«Отправить SOS всем 3 контактам или одному?»*
4. Ответьте **«всем»** → **«всё»** — подписчики получат сообщение

Если контактов ещё нет, навык скажет, что список пуст — сначала добавьте подписчиков по ссылке для друзей.

> 💡 До модерации навык уже работает у вас лично — на этом же аккаунте на колонке и в приложении Алисы, в режиме «черновик/тестирование».

### Шаг 6. Отправьте на модерацию (для публичного доступа)

Модерация нужна, только если навыком будут пользоваться другие люди. Для себя достаточно режима тестирования.

1. Вкладка **«Тестирование»** → убедитесь, что навык отвечает
2. Нажмите **«На модерацию»**
3. В комментарии для модератора укажите:

   ```
   Навык не требует авторизации. Для проверки скажите «всем», затем «всё» —
   будет отправлено тестовое уведомление подписчикам в мессенджер.
   ```

Модерация — 1–3 рабочих дня. После одобрения навык доступен всем по активационному имени.

### Если что-то не работает

| Симптом | Причина и решение |
|---|---|
| «Навык не отвечает» / «ошибка вебхука» | Сервис не запущен или URL недоступен. Проверьте `curl https://ваш-домен/health`. |
| Ответ «Неизвестный токен» (404) | В Webhook URL вставлен неполный/чужой токен. Скопируйте строку из сообщения бота заново. |
| «Аккаунт ещё не подтверждён» | Регистрация ждёт одобрения админом — дождитесь уведомления. |
| Алиса не распознаёт запуск | Смените активационное имя на 2–3 узнаваемых слова (шаг 2). |
| Навык отвечает, но SOS не приходит | Список контактов пуст — добавьте подписчиков по ссылке для друзей. |
| Сменили домен (`BASE_URL`) | Webhook-токен прежний, но домен другой — обновите Webhook URL в консоли. Токен можно посмотреть в боте: **📊 Статус**. |

## Функция ответов

1. Владелец через Алису отправляет SOS
2. Подписчик получает сообщение в Telegram и пишет боту любой текст
3. Бот немедленно пересылает ответ владельцу: `💬 Ответ от Имя: текст`
4. При следующем открытии навыка Алиса говорит: *«Есть N новых ответов. Зачитать?»*
5. Владелец говорит «да» → Алиса зачитывает все ответы по очереди
6. Алиса предлагает ответить каждому контакту голосом прямо через колонку
7. После ответов (или «пропустить») → проверяет наличие новых ответов → SOS-сценарий

### Кому уходит ответ подписчика

Если подписчик подписан на нескольких владельцев, бот выбирает адресата так:

- **один владелец, приславший SOS за последний час** → ответ уходит ему автоматически;
- **несколько владельцев прислали SOS за последний час** → бот спрашивает кнопками «Кому отправить ответ?»;
- **SOS за последний час не было** → ответ уходит тому, кто присылал SOS последним; если такого нет — бот спрашивает кнопками;
- **одна подписка** → ответ уходит ей сразу.

## Авточек (dead-man switch)

Необязательная функция, отключена по умолчанию.

**Включение:** `⚙️ Настройки → ⏰ Авточек → Включить → ввести время`

**Логика:**

| Время | Событие |
|---|---|
| T + 0 | Бот отправляет «👋 Всё в порядке?» с кнопками |
| T + 1 ч | Повтор: «⚠️ Вы не ответили час назад» |
| T + 1 ч 30 мин | Финал: «🚨 Последняя проверка, 10 минут до SOS» |
| T + 1 ч 40 мин | Автоматический SOS всем контактам |

**Подтверждение** (любое из):
- Кнопка «✅ Всё хорошо» в сообщении проверки
- Кнопка «🆘 Нужна помощь» → немедленный SOS
- Любой текст боту в период проверки

## Webhook при SOS (интеграции)

Каждый владелец может задать личный URL: `⚙️ Настройки → 🔗 Webhook при SOS`.
При каждом SOS бот отправляет на него `POST` с JSON — так можно подключить
что угодно на своей стороне:

- **Pushcut** → Ярлык на iPhone (SMS с геолокацией, звонок контакту)
- **IFTTT / n8n / Home Assistant** / умный дом
- собственный скрипт / сервер

**Payload:**

```json
{
  "event": "sos",              // "sos" | "test" | "auto" (авточек)
  "owner": "Маша",
  "owner_id": 123456789,
  "time": "2026-07-11T21:30:00+03:00",
  "message": "Застряла в лифте", // доп. сообщение (может быть пустым)
  "target": "Петя",             // имя контакта для варианта «Телефон» (иначе null)
  "phone": "+79991234567",      // номер контакта (если задан владельцем)
  "recipients": 3,               // скольким контактам доставлено (0 для «Телефон»)
  "failed": 0
}
```

### Вариант «Телефон» у Алисы

Если webhook задан, на вопрос Алисы «кому отправить» появляется третий вариант —
**«Телефон»**. Диалог:

```
Алиса: «Отправить SOS всем 3 контактам, одному или на телефон?»
Вы:    «Телефон»
Алиса: «Кому позвонить? Назовите имя. Доступные: Петя, Оля»
Вы:    «Пете»
Алиса: «Что передать Петя? Скажите сообщение или "без сообщения".»
Вы:    «Буду через 5 минут»
Алиса: «Отправляю на телефон контакту Петя. Держитесь!»
```

В этом случае бот **не** рассылает контактам в мессенджерах, а только шлёт webhook
с `target` = имя контакта и вашим сообщением. Ярлык на iPhone (через Pushcut)
находит этого человека в Контактах по имени и звонит/пишет ему SMS.

**Pushcut-автоформат.** Если URL ведёт на `api.pushcut.io`, бот автоматически
отправляет payload в формате Pushcut: `title` = «🆘 SOS: <имя>», `text` = сообщение,
`input` = полный JSON (для Ярлыка). Для других адресов payload уходит как есть.

### Телефон-мост через e-mail (полностью голосом, iPhone)

Самый «безручный» путь для дозвона с iPhone — **через письмо**. Настраивается в
`⚙️ Настройки → 📧 E-mail для дозвона` (нужен настроенный SMTP на сервере —
`SMTP_*` в `.env`).

Как работает:
1. У Алисы выбираете **«Телефон»** → контакт → сообщение.
2. Бот шлёт письмо на ваш адрес. Тема `SOS: <имя контакта>`, тело — строки:
   ```
   Телефон: +79991234567
   Сообщение: буду через 5 минут
   Контакт: Петя
   От: Маша
   ```
3. На iPhone **Команды → Автоматизация → E-mail** (Отправитель = адрес бота,
   Тема содержит `SOS`), режим **«Выполнять сразу»** → запускает Ярлык.
4. Ярлык берёт **номер** из письма и **звонит / шлёт SMS по номеру** — без касаний
   и без путаницы с одинаковыми именами в Контактах.

**Телефон у подписчика.** Владелец задаёт номер каждому контакту:
`👥 Контакты → 📞`. Именно этот номер уходит в письме (`Телефон:`) и в webhook
(`phone`), поэтому автоматизация звонит по конкретному номеру — даже если у вас
несколько контактов с одинаковым именем или несколько номеров.

Почему e-mail, а не Pushcut: у iOS есть штатный триггер автоматизации по письму
с режимом «Выполнять сразу» (без тапа) и без сторонних приложений. Поведение
действий (звонок/SMS без подтверждения) зависит от версии iOS — проверьте на
своём устройстве.

Пример Ярлыка: «Получить содержимое письма» → «Найти текст» по шаблону
`Телефон: (.+)` → «Позвонить [номер]» и/или «Отправить сообщение» (текст —
из строки `Сообщение:`).

Особенности:
- Запрос **fire-and-forget** — медленный или упавший webhook не задерживает и не ломает рассылку SOS.
- Разрешены только публичные `http(s)`-адреса; loopback и приватные сети блокируются (защита от SSRF).
- Проверить можно кнопкой «🆘 Тест SOS» — придёт payload с `event: "test"`.
- Таймаут запроса — 8 секунд, редиректы не выполняются.

> ⚠️ Это не заменяет 112. Пример с Pushcut удобен, но автодозвон на iPhone
> ограничен самой iOS (см. обсуждение в задачах проекта). Для реального вызова
> служб используйте штатный «Экстренный вызов — SOS» на телефоне.

```env
# SOS_MESSAGE=🆘 ТРЕВОГА! Мне нужна помощь!
# TZ_OFFSET=3
# CONTACTS_FILE=contacts.json
```

| Переменная | Обязательная | Описание |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | Да | Токен от @BotFather |
| `BASE_URL` | Да | Публичный HTTPS-адрес сервиса |
| `HOST` | Нет | Адрес для прослушивания (по умолчанию `0.0.0.0`) |
| `PORT` | Нет | Порт (по умолчанию `8000`) |
| `DB_PATH` | Нет | Путь к SQLite-файлу (по умолчанию `sos.db`) |
| `ADMIN_CHAT_ID` | Нет | Telegram-id админа; включает одобрение регистраций |
| `MAX_BOT_TOKEN` | Нет | Токен бота MAX; включает поддержку мессенджера MAX |
| `MAX_USERBOT_PHONE` | Нет | Номер сервисного MAX-аккаунта (PyMax userbot) — писать в MAX по телефону |
| `BACKUP_INTERVAL_HOURS` | Нет | Интервал авто-бэкапа в часах (0 — выкл.) |
| `BACKUP_PASSPHRASE` | Нет | Если задан — бэкапы шифруются (AES-256-GCM) |
| `SMTP_HOST` / `SMTP_PORT` | Нет | SMTP-сервер для e-mail «Телефон»-моста |
| `SMTP_SSL` | Нет | `true` для порта 465 (implicit TLS), иначе STARTTLS |
| `SMTP_USER` / `SMTP_PASSWORD` | Нет | Логин/пароль SMTP (пароль приложения) |
| `SMTP_FROM` | Нет | Адрес отправителя писем |

## Резервные копии

Всё состояние сервиса — в одной SQLite-базе `data/sos.db` (владельцы и их
webhook-токены, подписчики, ответы, авточек, лог SOS). База работает в режиме
**WAL**, поэтому просто скопировать файл «на живую» нельзя — нужен консистентный
снимок.

Есть два способа: **через самого бота** (удобно, приходит файлом в Telegram) и
**скриптами на сервере**.

### Через бота (админ, в личке)

Доступно только администратору (`ADMIN_CHAT_ID`).

- **`/backup`** — бот делает архив всех `.db` файлов (`.tar.gz`) и присылает его
  документом прямо в чат.
- **Авто-бэкап** — если задан `BACKUP_INTERVAL_HOURS`, бот сам присылает бэкап
  админу каждые N часов.
- **Шифрование** — если задан `BACKUP_PASSPHRASE`, архив шифруется (AES-256-GCM),
  расширение `.tar.gz.enc`. ⚠️ Без пароля такой бэкап восстановить нельзя — храните пароль отдельно.
- **Восстановление** — пришлите файл бэкапа боту как **документ**, указав в
  подписи `/restore`. Бот покажет кнопку **✅ Подтвердить восстановление**. При
  подтверждении он:
  1. делает страховочный бэкап текущего состояния (в `backups/`);
  2. приостанавливает работу с базой;
  3. распаковывает `.db` файлы из архива;
  4. перезапускает работу с базой;
  5. отчитывается, что восстановлено (число владельцев, контактов, ответов).

  Webhook-токены сохраняются — навыки Алисы продолжают работать.

### Скриптами на сервере

В репозитории есть готовые скрипты (полезно для cron и офлайн-хранения).

### Создать бэкап (без остановки сервиса)

```bash
cd /root/alisa_sos
./scripts/backup.sh
# ✅ Backup: backups/sos-20260711-030000.db
```

Скрипт делает консистентный снимок через `VACUUM INTO`, кладёт его в
`backups/` и хранит 30 последних. Папка `backups/` не попадает в git.

**Автоматически по расписанию** (ежедневно в 03:00) — добавьте в `crontab -e`:

```cron
0 3 * * * cd /root/alisa_sos && ./scripts/backup.sh >> /var/log/alisa-backup.log 2>&1
```

> Держите копии и вне сервера — например, периодически копируйте `backups/`
> на другой хост через `scp`/`rsync`.

### Восстановиться из бэкапа

```bash
cd /root/alisa_sos
./scripts/restore.sh backups/sos-20260711-030000.db
```

Скрипт остановит сервис, заменит базу, уберёт устаревшие WAL-файлы и запустит
сервис заново. Webhook-токены сохраняются — навыки Алисы продолжат работать без
перенастройки.

**Вручную**, если нужно:

```bash
docker compose down
cp backups/sos-ГГГГММДД-ЧЧММСС.db data/sos.db
rm -f data/sos.db-wal data/sos.db-shm       # убрать устаревший WAL
docker compose up -d
```

⚠️ Если у вас в `.env` изменён `DB_PATH`, поправьте пути в скриптах
(`scripts/backup.sh`, `scripts/restore.sh`) соответственно.

## Миграция из старой (однопользовательской) версии

Если в `.env` есть `ADMIN_CHAT_ID` — при первом запуске бот автоматически:
1. Создаёт запись владельца из переменных `OWNER_NAME`, `SOS_MESSAGE`, `TZ_OFFSET`
2. Импортирует контакты из `contacts.json`
3. Выводит в лог новый Webhook URL, который нужно вставить в Яндекс Диалоги

Миграция идемпотентна — повторный запуск ничего не делает.

```
migrate: created owner 123456789 (Маша)
migrate: contact Петя (987654321)
migrate: NEW WEBHOOK URL → https://sos.домен.ru/alice/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
migrate: Update this URL in your Yandex Dialogs skill settings!
```
